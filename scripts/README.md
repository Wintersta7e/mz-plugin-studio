# Scripts

`.github/workflows/ci.yml` runs every one of these except those marked as run by hand; run them locally directly or through the npm scripts named below (`npm run check` runs the local ones).

- `scripts/check-coverage.mjs` — run by `npm run test:coverage` and `npm run test:golden:coverage`; checks that coverage reports every tracked source file, that every source file with lines belongs to a floor directory, that each directory is at or above its line and branch floors, and that each golden-covered generator file is at or above its line floor; prints, for every floor, `floor <scope> <metric>: measured X%, floor Y%, slack Z%` (report only)
- `scripts/check-golden-commits.mjs` — `node scripts/check-golden-commits.mjs <base>..<head>`, or `--github-event` to take the range from a GitHub Actions event; checks that commits changing `src/` add no golden file or case, test-only commits delete no golden line, and user-visible golden changes carry a `CHANGELOG.md` change unless the commit is test-only and only adds whole cases (in a JSON golden, only adds lines); and that each commit's subject is at most 72 characters and its only trailer is `Co-Authored-By:` naming an allowed co-author, read from the whole body: a hyphenated `Some-Key:` line in any paragraph counts, as does every line of a last paragraph made only of `Key: value` lines (dependency-update bot commits are counted as skipped: in a pull request only when the bot opened it, elsewhere only when the hosting service committed them)
- `scripts/ci-policy.mjs` — `package <app.asar>` checks the packaged app's top-level entries, licence files and `node_modules/` size; `runtime-deps` (`npm run ci:runtime-deps`) checks that `dependencies` lists exactly the packages the main process and preload import; `toolchain [--electron]` (`npm run ci:toolchain`) checks that Node, `@types/node` and, with `--electron`, the Node inside Electron match `package.json` `engines`; `needs` checks that every job in `NEEDS_JSON` succeeded; `osv-ignores` checks that each `osv-scanner.toml` entry has an id, a reason and an `ignoreUntil` at most 90 days ahead; `fuses <executable>` checks that the packaged executable's Electron fuse wire holds the states the app requires.
- `scripts/e2e-prepare.mjs` — `npm run e2e:prepare` and CI; builds the unpacked release (`npm run e2e:prepare -- --reuse` reuses one present, for a build made earlier in the same job, as the Windows CI and release jobs do), writes the inspect-enabled copy and `dist/e2e-artifacts.json`, fails unless that fuse is the only difference or if a script the renderer page loads at start holds the code editor
- `scripts/e2e-visual-update.mjs` — `npm run e2e:visual:update [-- --check]`, run by hand; runs the visual project inside the pinned image and copies back only the Linux baselines
- `scripts/knip-scanned.mjs` — a knip reporter that `npm run knip:production` adds to print how many files the run analysed
- `scripts/strictness-status.mjs` — run by `npm run check` and CI's static job while lint suppressions exist; prints suppressed and pending counts and fails a rise in any (file, rule) suppression entry since the base commit without a lint config or lint package change (CI names the base in `STRICTNESS_BASE`: the pushed range's base, empty for the merge-base with `origin/main`; locally HEAD with uncommitted changes, else HEAD's parent), a pending count off the exact ceiling `pending-ceilings.json` holds for it (a pending flag without a ceiling and a ceiling without a pending flag fail too), or a pending flag already at zero, and a pending type-check that did not finish (killed, or stopped on an error without a location), printing how it ended and its last lines; `--report knip|jscpd|typecov` (`npm run knip:report`, `npm run jscpd:report`, `npm run typecov:report`) prints dead-code findings by type, the copied code's files scanned, clones, duplicated lines and share, and each program's type coverage, and fails only when a run printed no summary or report or scanned nothing, when the production-only knip run (`npm run knip:production`) is not exactly at the `--max-issues` ceiling its script names, or when the jscpd run (`npm run jscpd`) is not exactly at the `--clones` and `--duplicated-lines` ceilings `npm run jscpd:report` names
- `scripts/third-party-licenses.mjs` — `npm run licenses` after any lockfile change rewrites `THIRD_PARTY_LICENSES.md`; `npm run licenses -- --check` fails when it is stale.
